📐 Indian Railways IMBPS Architectural Principles
1. ML for Prediction $\rightarrow$ OR-Tools for Optimization $\rightarrow$ COA for Hard Constraints

Never use a single black-box ML model to create schedules. The ML layer answers "How long will it take, what is the asset risk, and what is its priority?" while Google OR-Tools CP-SAT answers "When and where can it be safely executed?" under strict COA headway, S&T disconnection, and power isolation constraints.

2. Multi-Department Co-location (Shared Piggybacked Blocks)

Whenever TMS Track Tamping is scheduled on a block section, IMBPS identifies compatible TDMS OHE Dropper renewals or SMMS Track Circuit / Bond testing to piggyback into the same window, maximizing the value of the track possession.

3. Continuous Governance & Safe Deployment

Models retrain on actual execution outcomes. New candidate models must pass the automated quality gate ($\text{Candidate MAE} \le \text{Production MAE}$) before promotion. In case of unexpected field drift, instant rollback to previous versions is supported.
